## 3. 关键设计取舍由谁决定

这些不是代码生成问题，而是判断题，记录在此便于评审追溯：

| 取舍 | 决定 | 理由 |
|---|---|---|
| 幂等域用 `asset_id` 而非请求 hash | AI 提议 → 实现中发现并修正 | 请求 hash 会让"改期后重提"产生第二份草稿，直接违背"只产生一份草稿" |
| 护栏放在状态机而非提示词 | AI 提议 → 人工确认方向 | 提示词只是请求模型自律，写进矩阵才是结构保证 |
| 离线 Mock 不作为 ReAct 证据 | 人工确认 | 题目明确 Mock 不证明模型效果，包装成已完成就是虚报 |
| 预算从 12 步改为双层上限 | AI 实测后发现并修正 | 12 步会在第 3 个素材截断，功能没跑完 |
| 诚实层"命中即报错"而非"替换" | AI 提议 → 人工确认 | 静默替换等于替模型撒谎，会掩盖越权 |

## 4. 验证结果（可复核）

| 验证项 | 命令 | 结果 |
|---|---|---|
| 单元与集成测试 | `python -m unittest discover -s tests -t . -v` | 324 项全绿 |
| 用例证据自动核验 | `python scripts/run_examples.py` | 29 项，0 失败 |
| 禁词扫描 | `test_no_publish_word` | `examples/run_*.txt` 的 `[stdout]` 段零命中 |
| 内部路径泄漏 | `test_examples_evidence` | `examples/` 内无沙箱路径、无 Windows 绝对路径 |
| 负向验证 | 人工注入"已发布"到输出段 | 被扫描器检出；仅污染说明行时不误报 |

负向验证这一步是刻意做的：只跑正向用例无法说明检查器"真的在检查"。

## 5. 边界与未验证项

1. **真实模型轨迹未取得**。本环境无外网、无 `OPENAI_API_KEY`，
   `LLMAdapter` 只通过假客户端验证了协议层（解析、修复、降级），
   真实模型的决策质量**没有任何数据**。这一点在 README 与 `03-evaluation.md` 同样标注。
2. **未做真实并发压测**。文件锁用多线程验证过（4 线程 × 5 次写不丢更新），
   但没有跨机器或长时间压力测试。
3. **未做 UI 与部署**。题目明示非必需，`02-solution.md` §10 只预留了接口。
